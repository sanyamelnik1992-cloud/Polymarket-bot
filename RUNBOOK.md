# RUNBOOK: бот для 5-минутных рынков Up/Down

Стратегия: **мейкер на справедливой цене по Chainlink** (подробности и доказательства — в `README.md`, раздел 4).
Бот ставит два бида, на Up и на Down, на `fair − h` (по умолчанию 4¢). Только post-only (никогда не платит тейкерскую
комиссию) и не лучше текущего лучшего бида. Котирует с 5-й по 240-ю секунду окна. Позиции держит до резолюции.

## 1. Режимы

| Режим | Что делает | Как включить |
|---|---|---|
| **paper v2** (рекомендуется) | То же, но с сильными фильтрами — лучший результат форвард-теста | `python scripts/run_bot.py --config config/paper_v2.toml` |
| **paper** (по умолчанию) | Читает живой рынок, «ставит» виртуальные заявки, считает исполнения по реальным сделкам (консервативно: только если сделка прошла *сквозь* нашу цену), задержка 150 мс | `python scripts/run_bot.py --config config/paper.toml --minutes 120` |
| **live** | Реальные ордера через официальный SDK `polymarket-client` | только после чек-листа ниже |

Отчёт по любому запуску: `python scripts/report_journal.py data/journal/<run>/`

## 2. Слои защиты

**Стратегия и фильтры** (`pmbot/bot/filters.py`; если не прошёл хотя бы один фильтр, котировки снимаются):
- свежесть данных: Chainlink ≤ 3.5 с, Binance ≤ 5 с, WebSocket стакана жив;
- страйк известен: опубликован Polymarket или посчитан минимум по 50 из 60 секунд Chainlink;
- спред Up и Down ≤ 3¢;
- |fair − середина стакана| ≤ 20¢ (бо́льшее расхождение — скорее ошибка модели, чем подарок рынка);
- скачок Binance больше 6σ за 1 с → пауза 3 с;
- волатильность больше 3 б.п./с → не котировать;
- P(Up) в диапазоне 5–95%; время в окне 5–240 с;
- XRP исключён (в тестах убыточен).

**Риск** (`pmbot/bot/risk.py`, значения в конфиге):
- `max_net_shares_per_window` — перекос Up/Down в одном окне;
- `max_cost_per_window` — сколько $ можно потратить на одно окно;
- `max_open_worst_loss` — худший убыток по всем незакрытым окнам **плюс** все висящие заявки (BTC/ETH/SOL коррелированы,
  поэтому лимит общий);
- `daily_loss_limit` — реализованный убыток за UTC-день → **kill switch** (снять всё и остановиться);
- `max_losing_windows_in_row` — серия убыточных окон → пауза `pause_after_losses_s`;
- `max_actions_per_sec` — лимит частоты ордеров;
- **kill-файл**: `touch STOP` → бот снимает все заявки и останавливается.

**Исполнение (live)** (`pmbot/bot/live.py`):
- каждый ордер **post-only** и **GTD**: истекает сам, даже если бот умер;
- **heartbeat** каждые 4 с: если бот перестал отвечать, биржа через ~10 с отменяет все ордера;
- `cancel_all` при старте, при остановке, при срабатывании kill switch и Ctrl+C;
- старт live запрещён, если: нет `--live` в CLI **и** `mode = "live"` в конфиге; нет
  `PMBOT_LIVE_CONFIRM=I_UNDERSTAND_REAL_MONEY_RISK`; нет ключа; `polymarket.com/api/geoblock` говорит `blocked`;
  баланс pUSD меньше `max_open_worst_loss`;
- приватный ключ берётся только из переменной окружения и никогда не пишется в журнал (это покрыто тестом).

## 3. Чек-лист перед реальными деньгами

1. **Юрисдикция.** Аккаунт и сервер — в стране, где Polymarket разрешает торговлю. Россия, США, Великобритания,
   Германия, Франция, Польша и др. — close-only (см. README). Обход через VPN нарушает правила и грозит заморозкой средств.
2. **Paper минимум 3–7 дней** на том сервере, где будет live. Критерии:
   - ROI > 0 и t-stat > 2 по окнам (`report_journal.py`);
   - плюс в большинстве дней, а не за счёт одного удачного часа;
   - максимальная просадка меньше `daily_loss_limit`.
3. **Отдельный кошелёк** только для бота, на нём ровно бюджет теста (например, $50–200). Лучше
   **Session Key** (beta): им можно торговать, но нельзя вывести средства. Основной ключ на сервер не кладём.
4. Скопировать `config/live.example.toml` → `config/live.toml`, **перенести в него секцию `[filters]` из
   `config/paper_v2.toml`** (без них v1 проиграла в форвард-тесте), проверить каждое число. Начать с `quote_size = 5`,
   `max_cost_per_window = 10`, `max_open_worst_loss = 40`, `daily_loss_limit = 20`.
5. Секреты — в `.env` (он в `.gitignore`) или в менеджере секретов:
   ```bash
   export PMBOT_PRIVATE_KEY=0x...        # ключ бота / session key
   export PMBOT_WALLET=0x...             # (опц.) адрес Deposit Wallet
   export PMBOT_LIVE_CONFIRM=I_UNDERSTAND_REAL_MONEY_RISK
   pip install polymarket-client==0.16.0
   python scripts/run_bot.py --config config/live.toml --live
   ```
6. Первые часы — под присмотром. Сверять реальные fills (`events.jsonl`, тип `fill`) с paper-ожиданиями.
   Если реальность заметно хуже — `touch STOP` и разбираться.
7. Увеличивать лимиты не чаще раза в неделю и только при выполнении критериев п.2 на живых деньгах.

## 4. Что может пойти не так

| Риск | Защита |
|---|---|
| Модель ошибается (базис, неверный страйк) | фильтр расхождения с рынком, страйк только из точного источника, лимиты на окно |
| Резкое движение, наши заявки устарели | jump-фильтр, моментальное понижение бидов, taker delay 150 мс на бирже |
| Бот/сервер упал с открытыми ордерами | heartbeat → автоотмена через ~10 с; GTD-экспирация |
| Серия неудач | дневной стоп, пауза после серии убытков, kill-файл |
| Обрыв данных | фильтры свежести → снятие котировок |
| Рестарт движка биржи (2 мин post-only) | все наши ордера и так post-only |
| Конкуренция за те же сделки (в paper её нет) | маленький старт и сверка реальных fills с paper |
| Ошибка в коде | 33 юнит-теста, paper по умолчанию, лимиты в $ на всё |

## 5. Что ещё не сделано (до live нужно доделать или проверить)

- реальный ордерный цикл ни разу не запускался на бирже (из этого окружения торговля заблокирована геоблоком);
  первый live-запуск — с минимальными лимитами;
- при старте live бот подгружает уже открытые позиции кошелька в 5m-окнах (Data API `/v2/positions`) и учитывает их
  в лимитах. Сверка «на лету» во время работы — только по своему user-стриму; это нужно проверить на первом live-запуске;
- самый быстрый источник Chainlink — PolyBolt (`price.crypto`, нужны API-ключи), сейчас используется RTDS (+~1.4 с);
- арбитраж 5m↔15m пока отдельно (`pmbot/arb_scanner.py`, только paper).
