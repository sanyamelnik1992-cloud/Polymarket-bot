# Инструменты отчёта 95

Лента публичных сделок BTC 5 мин + секундные цены Binance → «что заработал бы мейкер». Только публичные данные.

| скрипт | что делает |
|---|---|
| `fetch_tape.py FROM TO ПАПКА [монеты] [виды]` | итоги окон (Gamma) и все сделки тейкеров (data-api v2) → `windows.json`, `trades.json`; ~2 мин на 4 дня BTC 5 мин |
| `bn_fetch.py FROM TO OUT.npz СИМВОЛ...` | секундные цены Binance (`data.binance.vision`, текущий день через API) → `bn1s.npz` |
| `tape_table.py ПАПКА bn1s.npz OUT.npz` | каждая сделка как исполнение заявки мейкера: справедливая цена по Binance, исход, цена рынка по прошлым сделкам, движение Binance до сделки, маркаут |
| `tape_rules.py TABLE.npz...` | честная симуляция правил котирования (по своей цене заявки), по дням |
| `tape_regimes.py TABLE.npz [h_fav] [h_dog]` | калибровка модели и цены рынка, вес модели и рынка, разбор правила по режимам |
| `maker_profile.py [мин. сделок] [префикс...]` | как заполняются топ-мейкеры: сторона, движение Binance, секунда окна, цена (данные отчёта 89, нужны `who7_raw.json`, `outcomes.json`, `bn1s.npz`, `fairlib.py` в папке) |

Порядок: `bn_fetch.py 2026-11-17 2026-11-26 bn1s.npz BTCUSDT`, `fetch_tape.py 2026-11-22 2026-11-26 tape btc 5m`,
`tape_table.py tape bn1s.npz table.npz`, `tape_rules.py table.npz`, `tape_regimes.py table.npz`.

**Учёт.** Наша заявка стоит по `b = ref − h` и лучшая по цене, поэтому каждая сделка по цене `≤ b` исполняется у НАС по `b`. Итог на акцию =
исход − `b`, а не исход − цена сделки. Первая версия считала по цене сделки и завышала доход на «улучшение цены» (+2.6 ц вместо −1.5 ц у
симметричной заявки на справедливая − 1 ц). Объём на ленте — верхняя граница: проход по нескольким уровням даёт несколько строк.
Проверка учёта: правило «min» (живое до 26 ноября) на ленте 22–25 ноября даёт +0.32 ц на акцию, его бумажный близнец на сервере — +0.30 ц.
