# Инструменты отчёта 83

Данные — те же, что в отчёте 80. Как их получить, описано в `reports/80_tools/README.md`, шаги 4, 5 и 8:
- `bn1s.npz` — секундные цены Binance;
- `windows.json` — итоги 13 056 окон 9–16 ноября;
- `mtrades.json` — публичные покупки и продажи по рынку в последних минутах каждого окна.

Скрипты читают эти файлы из текущей папки. `zmod.py` — общие функции, копия из отчёта 80.

| скрипт | что считает |
|---|---|
| `wallets.py` | каждая сделка оценена по итогу окна; доход, дни в плюсе и стиль каждого кошелька → `wallets.json` |
| `fair.py` | доход сделок в зависимости от того, насколько цена была ниже или выше справедливой по Binance |
| `fair_lag.py` | то же, но цена Binance берётся за 0, 1, 2, 3 и 5 с до сделки (нет подглядывания в будущее) |
| `fair_days.py` | разница с ценой Binance от 10 ц: по дням, монетам, ценам, времени до конца, покупкам и продажам |
| `fv_bot.py` | повтор правила «Перехватчика»: один вход на окно, разные пороги, задержки, зоны и монеты |
| `who.py` | кто забирает отстающие цены: число кошельков, доля крупнейших, размер сделки, длительность отставания |

Справедливая цена стороны — Φ(z):
- z = ln(S / K) / (σ · √(τ0 + 19.5));
- S — цена Binance;
- K — среднее Binance за [T−62, T−3];
- σ — среднеквадратичное 10-секундных движений Binance за час, пересчитанное на 1 с;
- τ0 — секунды до начала закрывающего TWAP.

Доход сделки считается по итогу окна (Gamma), с комиссией 0.07·p·(1−p).

`fair_vs_trades.py SETTLES SINCE UNIT OUT.json` (раздел 11): для бумажных входов из `settles.csv` — были ли в том же окне публичные
сделки, забравшие предложение для нашей стороны по нашей цене или лучше (Gamma + data-api v2, нужен доступ в сеть).
