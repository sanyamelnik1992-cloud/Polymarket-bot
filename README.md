# Polymarket: разбор 5-минутных крипто-рынков, тесты стратегий и инструменты для бота

> Исследование от 4 ноября 2026. Данные: 72 часа истории (1–4 ноября 2026, 3 456 пятиминутных и
> 576 пятнадцатиминутных рынков, 1,94 млн сделок), плюс ~1.5 часа живой записи стаканов,
> цен Chainlink и Binance с миллисекундными метками.
> **Это не финансовый совет.** Все цифры — оценки по ограниченной выборке.

---

## TL;DR

1. **Ботов использовать можно и это норма.** У Polymarket официальный CLOB API, SDK для Python и TypeScript,
   страница для маркет-мейкеров, программа ребейтов. По оценкам on-chain аналитиков, большую часть объёма
   на 5-минутках дают боты.
2. **Но есть география.** Россия, США, Великобритания, Германия, Франция, Польша и ещё около 30 стран работают
   в режиме **close-only**: открывать новые позиции нельзя, ордера с таких IP отклоняются (ниже полный список).
   Обход блокировки (VPN и т.п.) нарушает ToS и грозит заморозкой средств.
3. **Простых денег нет.** Тейкеры в сумме проигрывают ровно на размер комиссии: −$473k за 3 дня
   при комиссиях $457k. До комиссий у них около нуля. 66% кошельков в минусе.
4. **Против простой модели рынок эффективен.** Модель справедливой цены по Binance с учётом TWAP-резолюции
   даёт edge, только если реагировать быстрее ~2 с. Живой стакан Polymarket подстраивается под Binance
   за **100–300 мс**, так что это гонка инфраструктуры.
5. **Наивный маркет-мейкинг** (цена по Binance с лагом 1–3 с) **теряет 7–14% от оборота** (t-stat от −15 до −40):
   сделки исполняются именно тогда, когда котировка устарела (adverse selection).
6. **Где деньги реально есть:**
   - **Профессиональный маркет-мейкинг.** Топовые мейкеры BTC 5m зарабатывают $2–4.6k в день
     (ROI 1–2.5% от исполненного объёма, примерно половина — ребейты). Пул ребейтов по BTC 5m — около $28k в день.
   - **Главная находка живого теста:** справедливая цена по **Chainlink** (источник резолюции) с nowcast по Binance
     предсказывает исход лучше середины стакана. Paper-мейкер на ней с реакцией 100 мс показал **+14% ROI (t≈3)**
     на 62 окнах (BTC +7%, ETH +44%, SOL +33%, XRP в минусе). При реакции 500 мс — около +5%,
     с ценой по Binance — около нуля.
   - **Бот на этой стратегии** (`pmbot/bot/`, `RUNBOOK.md`) прошёл форвард-тест в paper: базовая версия проиграла
     (−$23, остановлена kill switch), версия v2 с сильными фильтрами — **+$36 на 19 окнах (ROI +22%, t=1.7)**,
     худшее окно −$7. Обнадёживает, но ещё не доказано.
   - **Нашёл интересное: арбитраж «вложенных» рынков 5m↔15m.** В последние 5 минут 15-минутное окно и
     5-минутное окно с тем же концом резолвятся по **одной и той же** закрывающей TWAP (проверено: 576 из 576 пар).
     Значит, их цены обязаны быть монотонны. В 4.8% пар появлялось окно с **гарантированной** прибылью
     больше 1¢ после комиссий обеих ног (в среднем +6¢ на комплект). Объём небольшой. Для этого
     написан живой paper-сканер (`pmbot/arb_scanner.py`); за час живого теста возможностей не появилось.

## 1. Как устроен Polymarket (актуально на ноябрь 2026)

| Что | Как |
|---|---|
| Механика | Бинарные исходы (Up/Down, Yes/No) — токены на Polygon. Пара токенов = $1 (pUSD). Цена токена = вероятность. |
| Торговля | Центральная книга заявок (CLOB, `clob.polymarket.com`), off-chain матчинг, on-chain расчёт. Ордера GTC/GTD/FOK/FAK, post-only. |
| Деньги | **pUSD** на Polygon (депозит через бридж с разных сетей). |
| Комиссия | Только тейкер: `fee = shares × 0.07 × p × (1−p)` для крипто-рынков. При 50¢: 1.75¢ на акцию (**3.5% от суммы**), при 90¢: 0.63¢ (0.7%). Мейкер платит 0. Фактически по 5m: **1.96% от оборота тейкеров**. |
| Ребейт мейкерам | 20% тейкерских комиссий рынка делятся между мейкерами пропорционально «fee-equivalent» их исполненных заявок. Выплата ежедневно, минимум $1. |
| Liquidity Rewards | На 5m/15m крипто-рынках **нет** (`rewards_config = []`). |
| Taker delay | На крипто-рынках тейкерская заявка ждёт **150 мс** до матчинга (с 4 сентября 2026). Это защита мейкеров от снайперов. |
| Лимиты API | Щедрые: `POST /order` 5 000 запросов/10 с (burst), `/book` 1 500/10 с и т.д. |
| Маркет-дата | Gamma API (рынки), Data API **v2** (сделки, позиции; v1 отключён 2 ноября 2026), CLOB WebSocket (стакан), RTDS/PolyBolt (цены Chainlink). |

### 5-минутные рынки «Bitcoin/ETH/SOL/XRP Up or Down»

- Новое окно каждые 5 минут, slug вида `btc-updown-5m-<unix_start>`. Торги открываются примерно за сутки, основная активность — внутри окна.
- **Резолюция (с 14 августа 2026):** Up, если `TWAP60(конец) ≥ TWAP60(начало)`, по потоку Chainlink Data Streams `btc-usd-twap-60s`.
  «Цена для победы» (price to beat) окна = финальная TWAP предыдущего окна (совпадение 99.9%).
- Следствие: в последние 60 секунд часть финальной TWAP уже известна, исход «застывает». Модель это учитывает (`pmbot/model.py`).
- После конца окна резолюция приходит через ~80 секунд (иногда до 5 минут).
- 15m-рынки устроены так же (`btc-updown-15m-<ts>`), закрываются той же 60-секундной TWAP.
- **Часовые** рынки (`bitcoin-up-or-down-<date>-<h>am-et`) резолвятся иначе: по **свече Binance BTCUSDT 1H** (close ≥ open).

### Можно ли ботов? Да

API и SDK официальные, есть раздел «Market Making», батч-ордера, heartbeat с авто-отменой, Builder Program.
Ограничения: rate limits, self-trade prevention, режим post-only в течение 2 минут после рестартов движка.

### География (`GET https://polymarket.com/api/geoblock`)

- **Полный запрет:** Иран, Сирия, Куба, КНДР, Крым/Донецк/Луганск.
- **Close-only** (новые ордера отклоняются, и на сайте, и через API): Аргентина, Австралия, Беларусь, Бельгия, Бразилия,
  Канада (BC, ON, AB, QC), Германия, Франция, Италия, Польша, **Россия**, Сингапур, Словакия, Таиланд, Тайвань,
  Великобритания, **США**, Новая Зеландия и другие.
- Только сайт (API разрешён): Ирландия, Япония, Нидерланды, Южная Корея, Мальта (спорт).

Бот должен работать **легально из разрешённой юрисдикции** (и сервер, и владелец аккаунта).
Для США есть отдельная регулируемая площадка Polymarket US. Этот контейнер, кстати, в США (`blocked: true`):
он годится для сбора данных, но не для торговли.

### Ключевые наблюдения

**a) Модель справедливой цены** (`pmbot/model.py`). Цена — броуновское движение. До закрывающего окна TWAP
`log(C/S) ~ t(df=4)` с дисперсией `σ²·(τ + 60/3)`. Внутри окна учитывается уже накопленная часть TWAP.
На посекундной сетке модель хорошо откалибрована (`scripts/model_calibration.py`). Нюанс:
дисперсия Binance на горизонтах ≥30 с в ~1.65 раза больше, чем следует из 1-секундных доходностей (variance ratio).

**b) Binance ≠ Chainlink.** Резолюция идёт по Chainlink (агрегат бирж в USD), а у BTCUSDT на Binance
плавающий базис 1–5 б.п. к USD. Это сопоставимо с медианным движением за окно (4.8 б.п.).
Реконструкция исхода по Binance совпадает с фактом в 97–99%; ошибки — когда движение меньше 1 б.п.
Бывали случаи, когда Binance стоял на +3.5 б.п., а рынок уверенно ставил на Down и оказывался прав.
**Боту нужен поток Chainlink.** RTDS (`wss://ws-live-data.polymarket.com`, топик `crypto_prices_chainlink`)
отдаёт его без авторизации, TWAP по нему совпадает с официальной ценой с точностью 0.1–0.5 б.п. (8/8 окон).

**c) Задержки (живые данные).** Chainlink отстаёт от Binance примерно на 1 с, и RTDS доставляет его ещё через ~1.4 с.
Метка времени сделок в Data API = время матча + 2.2 с (1.0–3.8). Стакан Polymarket реагирует на движение Binance
за 100–300 мс.

**d) Почему наивный мейкер проигрывает.** Если поставить бид выше лучшего бида рынка (по своей модели),
вас исполняют ровно тогда, когда ваша модель ошибается: рынок, который держат быстрые боты, точнее.
Если встать в очередь на лучшую цену — уровень съедают, в основном, информированные «подметальщики».

**e) Вложенные рынки.** 5m-окно `[T+600, T+900]` и 15m-окно `[T, T+900]` закрываются одной TWAP `C`
(576/576 совпадений finalPrice). Это лестница бинарных опционов с разными страйками `O5` и `O15`:
- если `O15 ≤ O5`, то `P(15m Up) ≥ P(5m Up)`; покупка `15m Up + 5m Down` платит ≥ $1 в **любом** исходе
  (и $2, если `C` между страйками);
- зеркально при `O15 > O5`.

Нарушения случаются, когда страйки близки (|gap| < 2 б.п.) и стаканы расходятся. На истории — 27 из 567 пар,
в среднем +6¢ на комплект, максимум 29¢ в течение 70 секунд. Оценка сделана по ценам реальных тейкерских покупок
обеих ног с разницей во времени не больше 2 с, а не по стакану. Поэтому это верхняя оценка, и объём ограничен
глубиной стакана 15m-рынка. Живая проверка ниже.

Если страйки далеко друг от друга, комплект законно стоит больше $1: с заметной вероятностью он платит $2.
Арбитража тогда нет, но остаётся ставка на диапазон, и её можно оценивать моделью.

## 4. Живая проверка (paper, без реальных ордеров)

Запись 4 ноября 10:15–11:37 UTC: 58 зарезолвленных окон (по 14–15 на BTC/ETH/SOL/XRP), 24 083 живые сделки,
стаканы с мс-метками (`reports/10_live_analysis.txt`, `reports/11_live_maker_sim.txt`).

**Стакан.** Спред 1¢ (XRP 2¢), медианный размер лучшего аска: BTC ~300 акций, ETH ~45, SOL ~15, XRP ~10.
Сумма лучших асков Up+Down всегда ≥ 1.01, бидов ≤ 0.99: Polymarket зеркалит книги, арбитража комплекта нет.

**Скорость реакции.** Корреляция «доходность Binance за 500 мс → изменение середины Up» максимальна
через 300 мс для BTC и 100–200 мс для ETH/SOL/XRP, к 1 с исчезает.

**Кто лучше предсказывает исход** (log loss на 100-мс сетке, меньше = лучше):

| | середина стакана | модель по Binance | **модель Chainlink + nowcast Binance** |
|---|---:|---:|---:|
| все окна | 0.558 | 0.545 | **0.533** |
| ETH, 1–4 мин | 0.71–0.74 | 0.64–0.69 | **0.61–0.68** |
| последние 30–60 с | **лучше** | хуже | хуже |

Вне последней минуты модель на источнике резолюции бьёт стакан, особенно на тонких ETH/SOL.
В последней минуте лучше рынок: моя модель грубо учитывает уже накопленную TWAP, и в потоке RTDS бывают пропуски секунд.

**Распад edge тейкера по задержке** (живые сделки, на стороне которых модель видела >3¢ после комиссии):

| Задержка информации до матча | 0 мс | 250 мс | 500 мс | 1 с | 2 с | 4 с |
|---|---:|---:|---:|---:|---:|---:|
| fair = Binance | +10.8% (t 1.1) | +9.9% | +8.5% | +9.9% | +6.4% | +0.5% |
| **fair = Chainlink nowcast** | **+16.5% (t 2.5)** | **+15.2% (t 2.1)** | +13.0% (t 1.9) | **+12.2% (t 2.1)** | +5.9% (t 1.8) | +1.5% (t 1.0) |

По активам (Chainlink, 0 мс): BTC +12.9% ($3.8k на чужих сделках за 14 окон, t 1.6), **ETH +48% (t 2.2)**,
SOL +43% (t 1.4), XRP ~0.

**Paper-мейкер на реальном стакане** (`maker_sim.py`: два бида Up/Down на `fair − h`, post-only, задержка котировки,
исполнение только «насквозь»: сделка прошла по цене хуже нашей; лимит позиции 50; ребейты 20%):

| fair value | задержка | h = 0 | h = 2¢ | h = 4¢ |
|---|---|---:|---:|---:|
| Binance | 100 мс | +0.7% | +2.7% | +8.3% (t 1.5) |
| Binance | 500 мс | −3.6% | −0.8% | +1.8% |
| **Chainlink** | **100 мс** | +4.1% (t 1.6) | +6.8% (t 2.0) | **+14.2% (t 3.1)** |
| Chainlink | 500 мс | −1.1% | +1.1% | +4.6% (t 1.5) |

По активам (Chainlink, h=4¢, 100 мс): BTC +7.3% (t 1.8), ETH +44% (t 2.3), SOL +33% (t 2.3), **XRP −26%**.
Обе половины выборки в плюсе (+29% и +6%), но эффект слабеет. Абсолютные суммы маленькие: заявки по 10 акций,
~$2–4k исполненного объёма за 62 окна.

**Сканер арбитража 5m↔15m** (10:39–11:50): 20 пар, зазоры страйков 2.4–15.5 б.п., минимальная цена комплекта
с комиссиями 1.01. Возможностей не было. Это ожидаемо: на истории они появлялись почти только при зазоре < 2 б.п. (~5% пар).

**Как это согласуется с историей.** Исторический бэктест мейкера (−7…−14%) использовал только Binance с лагом 1–3 с.
Живой тест с ценой источника резолюции (Chainlink) и реакцией 100 мс показывает плюс.
Итог: **edge = точная справедливая цена по Chainlink + задержка ≤ 100–250 мс.** Без одного из двух — минус.

⚠️ Оговорки: 1.3 часа данных, одна рыночная фаза (спокойный BTC), перебор 64 конфигураций (риск подгонки),
модель очереди упрощена, конкуренция за те же сделки не моделируется.
Нужен **многодневный paper-прогон** на `pmbot/recorder.py` + `scripts/sim_maker_live.py` до вложения денег.

## 5. Рекомендации: что реализовывать

1. **Сначала юридический вопрос.** Определитесь, из какой юрисдикции и на чей аккаунт будет торговать бот.
   Проверка: `curl https://polymarket.com/api/geoblock` с сервера бота.
2. **Главный кандидат — мейкер на Chainlink-справедливой цене** (BTC/ETH/SOL, без XRP; на BTC 5m ребейты ~$28k в день):
   - справедливая цена = TWAP-модель (`pmbot/model.py`) на потоке Chainlink с nowcast по Binance/Coinbase.
     Самый быстрый источник — PolyBolt `price.crypto` / `price.crypto.twap` (нужны API-ключи CLOB);
     RTDS отдаёт Chainlink с опозданием ~1.4 с;
   - котировки **не лучше рынка**: на лучшем уровне или глубже (h ≈ 2–4¢). Глубокие заявки ловят агрессивных
     «подметальщиков», которые переплачивают. Плюс перекос по инвентарю;
   - отмена/перестановка за ≤ 100 мс после движения спота (taker delay 150 мс работает на мейкера);
   - отдельный режим для последней минуты окна (там рынок точнее модели) и для резких движений;
   - **сначала 3–7 дней paper-режима** (`scripts/record_live.py` → `scripts/sim_maker_live.py`, `scripts/analyze_live.py`).
     Критерий перехода к деньгам — положительный ROI с t > 2 в разные дни и при разной волатильности.
     Потом $1–5k реального капитала с жёсткими лимитами и сверкой реальных fills с симулятором.
3. **Дополнительная почти безрисковая стратегия: арбитраж 5m↔15m** (`pmbot/arb_scanner.py`, сейчас paper):
   - исполнение двумя FOK-ордерами одновременно (батч `POST /orders`) с обработкой «одна нога не исполнилась»;
   - оценить реальную частоту и ёмкость за 1–2 недели (за час живого теста возможностей не было);
   - расширить на 1h/4h/daily, где лестница длиннее (но источник резолюции там Binance — есть риск базиса).
4. **Не делать:** направленные ставки «по ощущению», покупку 95–99¢ «наверняка», тейкерскую торговлю по модели
   без субсекундной инфраструктуры, котировки «лучше рынка» по модели, модель только на Binance (проигрывает из-за базиса).

### Архитектура боевого бота (следующий этап)

```
 ┌─────────────── данные ───────────────┐   ┌──────── логика ────────┐   ┌──────── исполнение ────────┐
 │ Chainlink (RTDS / PolyBolt TWAP)     │──▶│ fair value: model.py   │──▶│ официальный SDK Polymarket │
 │ Binance + Coinbase WS (опережение)   │   │ (TWAP + nowcast)       │   │ post-only GTD, batch       │
 │ CLOB market WS (стаканы 5m/15m)      │──▶│ quote engine / arb     │   │ cancel-market, heartbeat   │
 │ CLOB user WS (свои fills)            │   │ inventory skew         │   │ (dead-man switch)          │
 └──────────────────────────────────────┘   └────────────────────────┘   └────────────────────────────┘
        риск-контур: geoblock-check на старте · лимит позиции на окно · дневной стоп · kill-switch
        «устаревший фид» (> N мс без Chainlink/Binance) → отменить все ордера · после рестарта движка — post-only 2 мин
```

Инфраструктура: VPS с минимальным RTT до `clob.polymarket.com` и до Binance (замерить из нескольких регионов),
WebSocket вместо polling, все решения в памяти, логирование каждого ордера и fill для сверки с paper-симулятором.

## 6. Бот (`pmbot/bot/`)

Боевая реализация стратегии «мейкер на Chainlink-справедливой цене» с фильтрами и риск-контуром.
Как запускать, какие стоят защиты и чек-лист перед реальными деньгами — в **[RUNBOOK.md](RUNBOOK.md)**.

```bash
python scripts/run_bot.py --config config/paper.toml --minutes 120     # paper (по умолчанию)
python scripts/report_journal.py data/journal/<run>/                    # отчёт по запуску
touch STOP                                                              # снять всё и остановиться
```

| Модуль | Назначение |
|---|---|
| `bot/config.py` | конфиг TOML + валидация (неизвестный ключ = ошибка) |
| `bot/state.py`, `bot/feeds.py` | стаканы CLOB (по сокету на актив), Chainlink (RTDS), Binance |
| `bot/fair.py` | P(Up): TWAP-модель на Chainlink + nowcast по Binance |
| `bot/filters.py` | 12 фильтров «можно ли сейчас котировать» |
| `bot/strategy.py` | два бида `fair − h`, post-only, не лучше рынка, перекос по инвентарю |
| `bot/risk.py` | лимиты на окно и общие, дневной стоп, пауза после серии убытков, лимит частоты, kill-файл |
| `bot/paper.py` | paper-исполнение по живым сделкам (консервативно, с задержками) |
| `bot/live.py` | реальные ордера через `polymarket-client` (post-only + GTD + heartbeat), за 5 «замками» |
| `bot/engine.py` | цикл: окна → страйки → fair → фильтры → риск → котировки → резолюция |

### Форвард-тест бота (paper, живой рынок, 4 ноября 12:15–15:00 UTC)

Честная проверка вне выборки, на которой подбирались параметры (`reports/12–15_*.txt`):

| Версия | Окон с позицией | PnL | ROI | t-stat | худшее окно | макс. просадка | Итог |
|---|---:|---:|---:|---:|---:|---:|---|
| v1, первые 11 мин | 6 | −$46.2 | −45% | −1.1 | −$30.7 | −$50.7 | перезапуск |
| v1 (`paper.toml`) | 25 | −$23.4 | −4.4% | −0.4 | −$32.0 | −$46.5 | **kill switch** по дневному лимиту в 13:16 |
| **v2** (`paper_v2.toml`) | 19 | **+$36.2** | **+21.8%** | +1.7 | −$7.4 | −$12.5 | доработала 140 мин |

- **v1 проиграла** из-за «метёлок»: модель на секунды становится слишком уверенной, бот встаёт бидом,
  информированные продавцы выбирают весь лимит окна ($30) на падающей стороне.
- **v2** (блок стороны после серии исполнений, фильтр нестабильной модели и всплеска волатильности,
  расхождение ≤ 10¢, лимит окна $12) в плюсе по всем трём активам: BTC +$24, ETH +$8, SOL +$4.
  Риск снизился в 4–5 раз. На 17 общих окнах: v1 −$0.8, v2 +$30.9 (разница шумная, t=0.55).
- v2 торговала только в 19 окнах из ~84. Больше всего времени бота держали вне рынка фильтры «модель расходится
  с рынком > 10¢» (~3 ч суммарно по окнам), «P вне 5–95%» и «скачок цены». Частые большие расхождения означают,
  что модель в быстрых движениях **переуверена**. Следующий шаг — откалибровать волатильность по 1 Гц-трассе `fv`
  (теперь пишется в журнал).
- **Вывод:** результат обнадёживающий, но не доказанный (19 окон, t=1.7 < 2). Защиты отработали вживую
  (kill switch, 26 блокировок токсичного потока). До реальных денег нужно 3–7 дней paper.

Быстрый старт:

```bash
pip install -r requirements.txt
python -m pytest -q tests
python scripts/collect_history.py data/hist 24 btc,eth           # 24 ч истории 5m
```

(иначе курсор уходит в глобальную ленту — легко ошибиться).
